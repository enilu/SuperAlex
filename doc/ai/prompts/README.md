# Prompts 目录说明

本目录存放项目内可复用的 Prompt 资产，用于沉淀"单轮、轻流程、输入输出清晰"的任务模板。

## 目录结构

```text
prompts/
├── project/     # 项目级 Prompt（结合仓库目录、分层和交付习惯）
├── tech/        # 技术栈级 Prompt
├── business/    # 业务域 Prompt
├── templates/   # Prompt 模板
└── README.md    # 本说明文件
```

## Prompt 适用边界

**适合沉淀为 Prompt：**
- 单轮、轻流程、输入输出清晰的任务模板
- 不依赖复杂执行步骤的分析、整理、设计、评审类任务
- 可以通过"目标 + 输入 + 约束 + 输出结构"稳定复用的任务

**不适合沉淀为 Prompt：**
- 已明显依赖多个步骤、多个文档和固定流程的任务
- 需要脚本化验证或强执行顺序的任务
- 只有一次性价值、没有复用价值的临时对话

## Prompt 最低结构要求

每个 Prompt 文件建议至少包含：
1. 元数据（id、name、type、level、status）
2. 目标
3. 适用场景
4. 输入要求
5. 上下文说明
6. 约束条件
7. 输出格式
8. Prompt 正文
9. 示例
10. 验收标准

## Prompt 编写原则

- 少写空泛角色描述，多写任务边界
- 少写"尽量"，多写"必须/禁止/输出为"
- 明确说明依赖哪些项目上下文
- 输出结构尽量固定，降低结果波动
- 能参数化的内容尽量参数化

## Prompt 与 Skill 的边界判断

- 如果内容已经依赖"先读 README → 再读多个规范 → 再分步执行 → 最后验证"，应沉淀为 Skill
- 如果内容主要是"给定输入材料，让 AI 按固定结构输出结果"，通常更适合沉淀为 Prompt
